# contexts 간소화 계획서

작성일: 2026-10-05 · 상태: 문서 변경 반영 · 전체 회귀 검사 미통과 · 커밋 미실행

**목표:** 기본 주입 지침과 불필요한 문서 조회를 줄이고, 저장소 고유 정보·출력 규격·검증 자산을 유지한다.

**구조:** 기존 경로와 배포 방식을 유지한 채 공통 지침부터 간소화한다. 도메인 문서는 작업별로 필요한 정보만 참조하도록 정리하고, 실행 가능한 검사와 회귀 테스트는 보존한다.

**기술:** Markdown, Ansible 심볼릭 링크 배포, Bash 검증 도구, Just.

**설계 근거:** 앞선 대화의 권고와 `contexts/README.md`의 유지보수 기준. 최신 모델의 기본 동작을 반복하는 지침보다 저장소 고유 정보와 실제 실패 방지책을 우선한다. 지침 감소가 성능 개선을 보장한다는 가정은 하지 않는다.

실행 시 체크박스 순서로 진행한다. 직접 실행에는 `superpowers:executing-plans`를 사용할 수 있다. 이 문서 작성 요청은 구현·배포·커밋·유료 평가 실행 요청을 포함하지 않는다.

## 1. 목표 및 성공 기준

### 선택한 접근

| 접근 | 장점 | 비용·한계 | 선택 |
|---|---|---|---|
| 기존 지침 유지 | 변경 비용 없음 | 일반론·중복·불필요한 절차가 남음 | 제외 |
| 경로를 유지하면서 단계적으로 간소화 | 배포 호환성과 검증 자산 보존, 작은 단위로 복구 가능 | 문서별 판단 필요 | 채택 |
| contexts 전체 폐기 및 재구축 | 가장 큰 구조 축소 가능 | 테스트·훅·배포 연결을 광범위하게 수정해야 함 | 이번 범위 제외 |

### 완료 조건

- 전역 지침에는 사용자 선호와 공통 실행 경계만 남긴다. 이 저장소 전용 명령·경로·기록 절차는 로컬 지침으로 옮긴다.
- 역할 선언, 인지 엔진 수사, 고정 답변 형식, 모든 작업에 적용하는 자가비판 절차를 제거하거나 필요한 작업 조건으로 한정한다.
- 유지한 규칙은 사용자 선호, 저장소 고유 정보, 구체적인 출력 계약, 확인된 실패 방지책 중 하나로 설명할 수 있어야 한다.
- SKILL.md의 사용 조건은 실제 작업과 대응하며, 작은 수정에도 전체 문서 트리를 읽게 하지 않는다.
- 기존 scripts·tests·evals·examples의 내용과 실행 계약은 보존한다.
- 린트 오류가 없고, 영향받는 기존 회귀 검사가 통과한다. 미실행 검사는 이유와 범위를 보고한다.
- 최종 diff에서 깨진 참조·폐기 조항 인용·보안 경계의 누락을 확인한다.
- 현재 배포는 링크 방식이므로 기존 파일 내용 변경에 재배포가 필요하지 않음을 확인한다. 파일명·등록 대상 변경은 이번 범위에서 피한다.

문서 길이와 MUST 개수는 보조 지표다. 목표 줄 수나 축소율을 맞추기 위해 유효한 규칙을 삭제하지 않는다.

### 범위 밖

스킬 폴더 이동·삭제, Ansible 배포 재설계, 외부 플러그인 변경, 훅 비활성화, provenance 도구 폐기, CI 검증 축소, 기술 정책의 무근거 완화는 포함하지 않는다. 검증 자산의 별도 위치 분리도 후속 작업으로 남긴다.

## 2. 영향 파일 및 배포 반영 경로

`ansible/roles/ai_agent/tasks/main.yml`을 조회한 결과를 기준으로 한다. 실제 사용자 환경에 해당 링크가 설치되어 있는지는 실행 단계에서 별도로 확인한다.

| 대상 | 역할 및 수정 방향 | 배포 |
|---|---|---|
| `contexts/base.AGENTS.md` | 전역 기본 지침 축소 | ~/.gemini/config/AGENTS.md, ~/.claude/CLAUDE.md, ~/.codex/AGENTS.md에 링크 |
| `contexts/dotfiles/SKILL.md` 및 references | 저장소 구조·검증 명령·로컬 실행 제약 수용 | 저장소 루트 AGENTS.md·CLAUDE.md가 SKILL.md를 링크. 글로벌 스킬 등록 제외 |
| `contexts/prompt-architect/SKILL.md` 및 references | 범용 메타 절차 축소, 참조·호환성·유료 평가 조건 유지 | 아래 글로벌 스킬 에셋 링크 방식 |
| `contexts/pre-flight-check/SKILL.md` | 검사 프로필·실행 명령·결과 판정 중심으로 유지 | 아래 글로벌 스킬 에셋 링크 방식 |
| aws·k8s·containers·observability·aiops의 SKILL.md 및 references | 일반 기술 지식과 정책을 분리, 작업별 참조 최소화 | 아래 글로벌 스킬 에셋 링크 방식 |
| `contexts/drawio-gen/SKILL.md` 및 references | 출력 규격·아이콘·배치·검증 계약 보존, 중복 일반론 정리 | 아래 글로벌 스킬 에셋 링크 방식 |
| `contexts/README.md`, `README.md` | 실제 적용 범위와 유지보수 설명 정합성 갱신 | 배포 대상 아님 |
| `contexts/INDEX.md` | 변경한 라우팅 표에서 재생성 | 배포 대상 아님 |

글로벌 스킬 에셋은 ~/.gemini/config/skills, ~/.claude/skills, ~/.agents/skills 아래 도메인별 폴더에 연결된다. 연결 대상은 SKILL.md·references·scripts·examples이며 tests·evals는 포함되지 않는다. 검사는 원본 저장소에서 실행한다.

기존 에셋은 심볼릭 링크이며 복사본 배포는 없다. 링크 대상의 내용 수정은 원본에 반영되지만, 진행 중인 세션이 이미 읽은 지침은 새 세션에서 확인해야 한다. 이번 계획은 `just setup`으로 사용자 환경 전체를 다시 구성하지 않는다.

## 3. 룰북 정합성 연쇄 영향

### 조항 판정 기준

| 조항 종류 | 처리 | 예시 |
|---|---|---|
| 사용자 선호 | 전역에 짧게 유지 | 한국어 답변·커밋 메시지 |
| 저장소 고유 정보 | dotfiles 로컬 지침으로 배치 | 원본 테스트 경로, quick/full 차이, 색인 갱신 명령 |
| 데이터·권한 경계 | 명확한 행동으로 유지 | 시크릿 노출 금지, 프라이빗 키 조회 승인, 사용자 변경 보존 |
| 출력 계약 및 구체적 실패 방지 | 해당 스킬에 유지 | draw.io XML·아이콘·배치 계약, 알람 검증 규칙 |
| 일반 기술 설명 | 판단에 필요한 참조로 축소 | AWS 설계 일반론, K8s 기본 지식 |
| 역할·수사·중복 절차 | 삭제 | Senior 역할 선언, 인지 엔진 태그, 반복적인 자가비판 |
| 설계 선택의 고정 선호 | 사용자 정책 여부를 확인해 조건화 | 항상 관리형 서비스 우선, 모든 설계에 동일한 가용성 조건 |

보안·아키텍처 조항이 일반적으로 보인다는 이유만으로 없애지 않는다. 실행 도구가 강제하는 정책인지, 사용자의 명시적 정책인지, 단순 권고인지 구분한다. 도구의 필수 검사는 이번 작업에서 완화하지 않는다.

### 참조 및 린터 연결

- base.AGENTS.md의 장 번호 인용이 dotfiles 코어·보안 문서에 있다. 장을 줄이거나 이동하면 인용도 같은 변경에서 갱신한다.
- 룰 이동 시 같은 내용의 전역·로컬 복사본을 만들지 않는다. 전역 선호와 로컬 실행 방법을 구분한다.
- provenance 기록은 전역 강제에서 dotfiles의 해당 작업 조건으로 옮긴다. `bin/utils/record-provenance.sh`, 편집 이력 훅과 관련 테스트는 보존한다.
- references 파일과 번호 접두사는 유지한다. 통폐합이 유리하더라도 우선 내용과 라우팅만 정리해 배포·인용 변경을 줄인다.
- `bin/linters/prompt-lint.sh`의 `check_ssot_module_lists()`는 특정 자가비판 선언과 실제 파일 번호를 비교한다. 이번 단계에서는 선언을 짧은 참조 점검 안내로 유지하며 번호 목록을 실제 파일에 맞춘다. 검사 통과를 위해 새 자가비판 절차를 추가하지 않는다.
- 새 references 파일이 필요해지면 파일·SKILL.md 라우팅 행·코어 모듈 목록을 함께 갱신한다. 현재 계획은 신설을 요구하지 않는다.
- description 변경은 `contexts/prompt-architect/evals/routing/cases.tsv`의 기대 라우팅과 대조한다. 정답지를 바꿔 오탐을 숨기지 않는다.
- 라우팅 표 변경 후 `just docs-index`로 INDEX.md를 안전하게 재생성한다.

- [ ] 아래 5번의 프롬프트 린트·라우팅 정답지·prompt-architect 회귀 검사를 실행해 기존 실패와 새 실패를 구분한다.
- [ ] base.AGENTS.md 인용과 provenance 호출부를 검색해 영향 목록을 작업 기록에 남긴다.

산출물: 시작 상태·기존 검증 결과·조항별 유지/이동/삭제 판정. 별도의 대형 감사 시스템은 만들지 않는다.

### 작업 2: 전역 지침과 로컬 지침 정리

수정: `contexts/base.AGENTS.md`, `contexts/dotfiles/SKILL.md`, dotfiles references.

- [ ] base에서 한국어 선호·시크릿/권한 경계·사용자 변경 보존·관련 검증과 미검증 보고·커밋 선호를 간결하게 유지한다.
- [ ] 룰 근거 기록, 테스트 원본 경로, /learn 연동 등 저장소 고유 내용은 dotfiles 진입점 또는 해당 참조로 이동한다.
- [ ] 고정 3회 재시도와 실패 보고 템플릿은 원인에 따른 재시도·필요한 개입 보고로 정리한다. 계속 실패하는 검사를 숨기거나 통과로 보고하지 않는 원칙은 유지한다.
- [ ] dotfiles SKILL.md에 구조와 핵심 검증 명령을 직접 안내해, 간단한 작업에서 코어 문서까지 필수 조회하지 않아도 되게 한다.
- [ ] 코어 문서의 역할 선언·인지 엔진 태그·중복 공통 지침을 제거하고, base 장 번호 인용을 갱신한다.
- [ ] private key 조회 승인·시크릿 분리·공급망 검증·사용자 변경 보호가 남아 있는지 수정 대상 문서를 직접 확인한다.
- [ ] 프롬프트 린트와 영향받는 기존 문서·색인 회귀 검사를 실행한다.

산출물: 전역에서 적용할 짧은 사용자 기본값과 저장소 내부의 실행 안내.

### 작업 3: 범용 메타 절차 및 검증 안내 축소

수정: `contexts/prompt-architect/SKILL.md`와 references, `contexts/pre-flight-check/SKILL.md`.

- [ ] prompt-architect의 발동 조건을 프롬프트·룰북 작업 중심으로 좁힌다. 일반 셸 작업은 필요할 때 셸 참조를 읽도록 하며, 해당 description과 라우팅 케이스를 함께 검토한다.
- [ ] 프로젝트 계획서 규칙은 배포 경로·검증·롤백처럼 이 저장소에서 필요한 내용 중심으로 줄인다. 모든 계획에 동일한 출력 목차나 예시를 강제하는 부분을 정리한다.
- [ ] 이미 간소화된 참조는 재작성하지 않고, 남은 역할 선언·태그·불필요한 형식 강제만 정리한다.
- [ ] 프롬프트 참조 무결성·frontmatter 호환성·유료 평가 명시 요청 조건은 보존한다.
- [ ] pre-flight-check는 quick/full 범위, 변경 파일 검사, 종료 코드 및 스킵 판정, 자동 훅이 없을 때의 수동 명령을 유지한다. 일반적인 보고 절차는 반복하지 않는다.
- [ ] 프롬프트 린트·prompt-architect 회귀·라우팅 정답지 검사를 실행한다. description 분석은 실제 모델 호출 평가와 구분한다.

산출물: 구체적인 작업 조건과 실행 계약을 가진 메타·검증 스킬.

### 작업 4: 도메인 참조 정리

순서: aws → k8s → containers → observability → aiops → drawio-gen. 각 도메인 변경은 독립적으로 검증한다.

- [ ] 각 SKILL.md와 연결된 참조를 읽고 3번 기준으로 조항을 판정한다. 첫 도메인의 판정 결과를 나머지에도 일관되게 적용한다.
- [ ] 역할 선언, 고정 답변 형식, 다른 스킬과 겹치는 기본 기술 설명·반복 점검을 제거한다.
- [ ] AWS 6개 기둥 설명 강제·관리형 서비스 우선·고정 AZ 요구처럼 설계를 일률적으로 결정하는 지침은 해당 요구가 있는 작업에 한정한다. 실제 보안 검사나 사용자 정책은 보존한다.
- [ ] 검증 스크립트가 요구하는 입력 조건과 출력 계약은 유지한다. scripts·tests·evals·examples는 변경하지 않는다.
- [ ] drawio-gen은 규격·아이콘 라이브러리·레이아웃 계산·검증 절차를 우선 보존하고 일반적인 수사만 정리한다. 문서량이 많다는 이유로 라이브러리를 삭제하지 않는다.
- [ ] 도메인별 프롬프트 린트를 실행하고 기존 tests/run.sh를 실행한다. 외부 도구 미설치로 건너뛴 검사는 구분해 보고한다.

산출물: 작업별 고유 정보와 실제 검증 조건을 중심으로 정리한 도메인 스킬.

## 5. 검증

### 로컬 정합성 및 회귀

아래 명령은 저장소 루트의 Bash 실행 환경에서 수행한다. Windows에서는 Git Bash 또는 WSL의 도구 가용성을 먼저 확인한다. 읽기 전용 문서 변경의 검증 때문에 setup이나 실제 인프라 배포를 실행하지 않는다.

```bash
git status --short
bash bin/linters/prompt-lint.sh
bash contexts/prompt-architect/tests/run.sh
bash contexts/prompt-architect/evals/routing/run.sh --check-cases-only
```

라우팅 표 수정 후:

```bash
just docs-index
bash contexts/dotfiles/tests/test-generate-context-index.sh
git diff --check
git diff -- contexts README.md
rg -n 'base\.AGENTS\.md|record-provenance|자가 비판 절차' contexts README.md
```

도메인별 변경 후 해당 `contexts/<도메인>/tests/run.sh`를 실제 도메인 경로로 실행한다. 전체 정리 후에는 `just test`로 보존된 검증 자산의 회귀를 확인한다. PASS 문구만 보지 않고 종료 코드·마지막 요약·WARNING의 스킵 원인을 확인한다.

성공 기준: 린트 오류 없음, 기존 회귀 검사 통과, 색인 경로 정합성, 의미가 없어진 인용 없음. 일반 셸 작업의 라우팅 기대가 바뀌면 정답지 변경 이유를 diff에 명시한다. 정적 라우팅 검사는 실제 모델의 발동 정확도를 증명하지 않는다.

이번 계획은 스크립트 수정을 요구하지 않는다. 구현 중 필수 스크립트 변경이 발견되면 별도 변경으로 분리하고 shellcheck·해당 회귀 테스트·run-suite 실행·격리 환경의 2회 연속 실행 멱등성 확인을 추가한다.

### 행동 비교

성능 개선을 주장하려면 아래 대표 작업을 기존 지침과 간소화 지침의 새 세션에서 비교한다. 같은 모델·추론 수준·입력·저장소 시작 상태·도구 환경을 사용하고, 외부 플러그인 지침도 동일하게 유지한다. 전역 링크가 원본 변경을 즉시 반영하므로 실행 중인 세션과 검증 기준을 혼합하지 않는다.

| 대표 작업 | 확인할 결과 |
|---|---|
| 작은 셸 오류 수정 | 최소 수정, 관련 검사, 불필요한 메타 스킬 조회 감소 |
| 도구 버전 변경 | pin·설정·관련 테스트 정합성 유지 |
| Terraform 리소스 변경 | 관련 보안·의존성 조건과 검증 유지 |
| 알람 규칙 변경 | 기존 검증기가 기대하는 필수 조건 유지 |
| draw.io 다이어그램 작성 | XML·아이콘·배치 규격과 검증 결과 유지 |
| 코드 수정 없는 질문 | 불필요한 스킬 호출·계획 문서 생성 없음 |

기록 항목: 작업 성공 여부, 재수정 요청, 불필요한 질문, 참조 조회·도구 호출 수, 경과 시간, 확인 가능한 토큰·비용. 환경 문제에 따른 실패는 구분한다. 안전·출력 계약 회귀가 있으면 해당 조항을 복원하고 비교한다. 소수 사례의 결과를 전체 작업의 성능 향상으로 일반화하지 않는다.

실제 에이전트 평가에는 비용이 들 수 있다. 이 계획 작성 중에는 실행하지 않으며, `contexts/prompt-architect/evals/routing/measure.sh`는 별도 명시 요청이 있을 때만 실행한다. 모델 비교를 수행하지 않았다면 결과는 “문서 정합성 검증 완료, 행동 개선 미측정”으로 보고한다.

## 6. 롤백

- 작업 1에서 기록한 시작 커밋과 사용자 변경 목록을 기준으로 복구한다. 사용자 변경이 섞인 파일은 이번 변경 부분만 역적용한다.
- 커밋 전에는 이번 수정 대상만 시작 상태로 복원한다. `git restore`는 사용자 변경이 없는 것으로 확인한 파일에만 사용하고, 저장소 전체 restore/reset을 하지 않는다.
- 커밋 후에는 해당 변경 커밋을 revert한다. 이전에 사용자 변경이 섞이지 않도록 커밋 단위를 분리한다.
- INDEX.md는 복원한 SKILL.md에서 `just docs-index`로 다시 생성한다. 프롬프트 린트와 해당 회귀 검사를 재실행한다.
- 기존 심볼릭 링크는 복원된 원본을 그대로 가리키므로 내용 복원에 setup 재실행은 필요하지 않다. 복원한 지침으로 새 세션을 시작한다.
- 계획을 벗어나 경로·링크 배포를 변경했다면 먼저 실제 변경 목록을 확인하고 해당 링크만 복원한다. 사용자 환경 전체 setup은 필요성과 실행 범위를 별도로 확인한다.

복구 단위는 전역·로컬 지침, 메타·검증 스킬, 개별 도메인이다. 특정 도메인에서 문제가 생겼다는 이유로 이미 확인된 다른 도메인까지 일괄 복구하지 않는다.
