# dotfiles 변경과 근거 기록

공통 사용자 선호와 실행 경계는 `base.AGENTS.md`를 따른다.

- **[PREFER] 공통 자가 비판 절차 (전 dotfiles 모듈 SSOT):** 참조 모듈(020, 030, 040, 050, 060) 중 현재 작업의 기준만 확인한다. 전체 문서 조회나 별도 자가비판 출력은 필요하지 않다.
- 결함 클래스를 수정하는 요청이면 같은 종류의 다른 위치를 한 번 검색한다. 특정 위치만 지정한 요청은 그 범위에 한정하고 범위 밖 발견은 보고한다.
- 이 저장소의 보안·아키텍처 규칙에 대해 사용자가 예외를 승인하면 `tech-debt-log.md`에 일자·규칙·승인 이유·상환 계획을 기록한다.

## 룰 근거 기록

- 특정 `contexts/` 룰을 근거로 코드를 수정했으면 `record-provenance.sh <file_path> <rule_source> <purpose>`로 기록한다. rule_source는 `<스킬>/<파일명>`이며 여러 근거는 콤마로 구분한다. 직접 지시·오타 수정처럼 대응 룰이 없으면 생략한다.
- 변경 근거를 질문받으면 저장소 루트 `.agent-state/edits.log`의 해당 이력을 확인한다. 룰 관련 실패가 반복되면 최근 20줄과 해당 룰을 확인해 개정안을 제안한다.
- `/learn`으로 룰 수정 제안서를 작성할 때는 `prompt-architect` 스킬을 참조한다.
