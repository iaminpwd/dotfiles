# dotfiles 작업 계획서

사용자 지정 형식과 저장소 관례를 따른다. 실행자가 알기 어려운 배포 연결과 검증 제약을 포함한다.

- 목표와 성공 기준, 수정·신설 파일, 실행 순서, 검증 명령과 기대 결과, 롤백 방법을 구체적으로 적는다. 간단한 작업에 별도 파일이나 고정 목차를 강제하지 않는다.
- `ansible/roles/ai_agent/tasks/main.yml`에서 실제 배포 방식을 확인한다. 심볼릭 링크 대상 내용 변경과 경로·등록 변경을 구분하고, 복사본 배포가 있으면 재배포와 원본 대조를 계획한다.
- 새 references 모듈은 파일·SKILL.md 라우팅 행·해당 코어의 SSOT 번호 목록을 함께 갱신한다. 삭제·이름 변경은 인용과 호출부까지 확인하고 `just docs-index`로 색인을 갱신한다.
- 기존 파일 경로는 실제 존재 여부를 확인한다. 신규 경로는 생성 대상으로 표시한다. 검증 명령은 계획서의 예제가 아닌 수정 대상 파일을 검사한다.
- 셸 스크립트 변경은 shellcheck, 관련 회귀 테스트와 run-suite, 격리 환경의 2회 연속 실행 멱등성 검사를 포함한다.
- 복구는 이번 변경에 한정하고 사용자 변경을 보존한다. 기존 링크 대상 내용만 되돌리면 setup 재실행은 필요하지 않으며, 배포 경로 변경은 해당 연결의 복구 방법을 명시한다.
