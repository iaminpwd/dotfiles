# DrawIO 레이아웃 계산 및 배치 검증 표준

본 모듈은 010-drawio-xml-standard.md에서 분리되었습니다(050 §6 정량적 크기 제약: 158줄 초과). 010이 "무엇을 어떤 태그·색·라벨로 그리는가"라는 XML 포맷 규격을 다룬다면, 본 모듈은 **그 요소들을 화면 어디에 얼마 크기로 놓는가**를 다룹니다.

실제 생성 후 렌더링 검증 과정에서 반복적으로 발견된 좌표 계산 버그(빈 공간 과다, 형제 컨테이너 겹침/계단식 정렬, 헤더-자식 텍스트 겹침)를 영구적으로 해결하기 위한 규칙임. 노드 수가 5개를 넘는 다이어그램에서는 좌표를 손으로 하나씩 정하는 대신 아래 원칙에 따라 스크립트로 역산할 것.

## 1. 공용 툴킷 사용

- **[MUST] 공용 툴킷 재사용**: 아래 원칙을 매번 새로 구현하는 대신 `layout_toolkit.py`를 `import`해서 쓰십시오. `grid()`/`hstack()`/`vstack()`/`offset_by_header()`/`subnet_box_size()`가 이미 구현되어 있고, `validate(path)`가 090 검증(ID 중복/끊어진 참조) + 형제 노드 겹침 검사를 한 번에 수행함.

## 2. 컨테이너 크기 및 정렬

- **[MUST] 컨테이너 크기는 콘텐츠로부터 역산**: 컨테이너의 `width`/`height`는 하드코딩 대신, 내부 아이콘 개수·격자 배치·노트 텍스트 줄 수로부터 필요한 크기를 동적 계산한 뒤 여백(padding)을 더해서 결정할 것. [Bad] `height=1720` 임의 지정 → 콘텐츠가 830px에서 끝나 890px가 빈 배경으로 남음. [Good] `header + content_height(아이콘 격자에서 계산) + bottom_padding` 공식으로 산출.
- **[MUST] 헤더 높이만큼 자식 y 오프셋 필수**: 자식 요소를 부모 컨테이너에 배치할 때, y좌표는 반드시 부모의 `startSize`(헤더 높이, 010 §2.1 표) 이상에서 시작해야 합니다. 이를 빼먹으면 부모 제목 텍스트와 첫 번째 자식의 헤더 텍스트가 겹칩니다.
- **[MUST] 같은 시각적 행(row)의 형제 컨테이너는 높이를 통일 (단, 콘텐츠 격차가 클 때는 예외)**: 나란히 배치되는 형제 서브넷/컨테이너들은 원칙적으로 그 행에서 가장 콘텐츠가 큰 것의 높이에 맞춰 동일한 높이로 늘리십시오(짧은 쪽은 여백이 남는 것을 허용). 단, 형제 간 콘텐츠 크기(너비 또는 높이) 격차가 1.8배를 넘으면 억지로 같은 행에 묶어 정렬하는 대신, 콘텐츠 크기가 비슷한 것끼리 재그룹하여 별도 행으로 분리할 것(예: 아이콘 1~2개짜리 작은 서브넷들끼리 한 행, 아이콘 4~5개짜리 큰 서브넷들끼리 한 행). 이 규칙을 지키지 않으면 아이콘 2개짜리 서브넷이 아이콘 5개짜리 서브넷과 같은 크기로 강제 확장되어 내부가 텅 비어 보이는 문제가 실제로 발생했습니다.
  - **[MUST] `row_height()`로 계산만 하고 마무리하는 대신 `uniform_row()`로 실제 반영**: `row_height(*heights)`는 통일할 값을 계산해줄 뿐, 그 값을 각 컨테이너의 실제 `height` 인자에 되돌려 적용하는 것은 호출자 책임임. his-infra 재생성 작업에서 행 간격(vstack) 계산에만 최댓값을 쓰고 정작 각 서브넷 컨테이너의 `height`에는 자기 자신의 원래(더 작은) 값을 그대로 써서, 같은 행인데 바닥선이 어긋나는 회귀가 실제로 발생했습니다. "계산은 했지만 적용을 잊는" 실수를 막기 위해, 값 계산과 반영을 한 번에 강제하는 `uniform_row(*wh_pairs)` — `(w, h)` 목록을 받아 높이가 통일된 `(w, h)` 목록을 반환 — 를 사용하고, 그 반환값을 그대로 각 컨테이너 생성 호출의 `width`/`height` 인자로 넘기십시오. `row_height()`를 직접 쓰는 경우에도 그 반환값을 반드시 모든 형제의 실제 height 인자에 대입했는지 확인할 것.
- **[MUST] 컨테이너 원형 규격 유지**: 컨테이너 크기는 항상 자신의 콘텐츠 기준으로 역산하고, 형제 정렬·그리드 폭 통일 등 시각적 정렬이 필요할 때는 컨테이너 자체를 강제로 늘리는 대신 좌측 정렬 후 남는 공간을 부모 컨테이너의 여백으로 보존할 것.
- **[MUST] 세로로 쌓인 여러 행의 폭 정렬**: 콘텐츠 크기 격차 때문에 형제를 여러 행(예: 대형 티어 행, 소형 티어 행)으로 나눠 배치할 때, 각 행의 아이템 개수가 다르면 hstack 결과 폭이 행마다 달라져 오른쪽 끝이 계단식으로 어긋나 보임. 이 경우 박스 크기를 늘리는 대신 **hstack의 gap을 균등하게 늘려서** 각 행의 전체 폭(`hstack`이 반환하는 두 번째 값)을 통일할 것. "컨테이너 원형 규격 유지" 규칙은 개별 박스 크기에 적용되는 것이지, 행 사이 간격 조정까지 제한하는 것이 아닙니다.

## 3. 배치 및 간격

- **[MUST] 형제 간 간격은 고정 gap 상수로 관리**: 같은 레벨의 형제 요소 사이 x/y 간격은 매번 다른 숫자를 즉흥적으로 지정하는 대신, 레벨별 gap 상수(예: 아이콘 간 30px, 서브넷 간 30px, 행 간 25px)를 정해 일관되게 적용할 것. 간격이 아이콘 크기보다 좁으면(예: 형제 컨테이너 사이 40px 간격에 60px 아이콘을 끼워 넣는 등) 옆 컨테이너 영역과 겹쳐 보임.
- **[MUST] 노드 5개 초과 시 격자/스택 계산 함수 사용**: 아이콘을 한 줄로만 늘어놓는 대신 `cols` 지정 격자 배치 함수로 감싸고, 서브넷/컨테이너 여러 개를 배치할 때도 가로 스택(hstack)·세로 스택(vstack) 헬퍼로 좌표를 계산할 것. 손으로 좌표를 하나씩 대입하면 간격 불일치·겹침·오프셋 누락이 반복적으로 발생함.
- **[PREFER] 다이어그램 종횡비 가드레일**: 전체 다이어그램이 세로로 지나치게 길어지지 않도록 레이아웃을 관리할 것(세로:가로 비율 1.4:1 이하 권장). 한 컨테이너 내부의 서브넷이 5개를 초과하면 2열 고정 그리드보다 콘텐츠 크기 티어(위 규칙)에 맞춘 다열 배치를 우선 검토할 것.
- **[PREFER] VPC/VNet 등 최상위 대형 컨테이너는 기본적으로 세로 배치(스택) 우선**: Region 안에 VPC/VNet처럼 그 자체로 서브넷을 여러 개 품는 대형 컨테이너가 2개 이상이면, 기본값으로 위아래로 쌓으십시오(사용자가 스타일 기준으로 지목한 참고 다이어그램 `his-infra-architecture선.drawio`도 VPC1/VPC2를 세로로 쌓아 전체 캔버스가 1800×1600으로 균형 잡힌 비율이었습니다). 가로로 나란히 배치하는 것은, 세로로 쌓았을 때 전체 캔버스가 위 종횡비 가드레일(1.4:1)을 벗어날 정도로 세로가 길어지는 경우에 한해 예외적으로 검토할 것. 실제로 VPC1/VPC2를 가로 배치했다가 캔버스가 2100×980(가로 2.1:1)까지 옆으로 퍼져 "옆으로 너무 긴" 결과가 나온 사례가 있었습니다.

## 4. 엣지 라우팅 및 접점

- **[MUST] 장거리 엣지는 waypoint로 경로 고정**: Region 레벨 아이콘 ↔ Subnet 내부 리소스처럼 2단계 이상의 컨테이너 경계를 가로지르는 엣지는 자동 라우팅에 위임하는 대신 waypoint로 경로를 명확히 고정할 것. `layout_toolkit.py`의 `edge()` 헬퍼의 `points` 인자로 최소 1~2개의 중간 경유점(부모 컨테이너 좌표계 기준)을 지정해, 선이 다른 컨테이너를 뚫고 지나가며 경로의 명확성을 확보할 것.
- **[MUST] 여러 엣지가 한 타겟에 모이면 각각 실제 중점을 waypoint로 명시**: `render_preview()`는 waypoint 없는 2점 엣지의 라벨을 `pts[len(pts)//2]`(경유점이 없으면 결국 타겟 중심)에 그린다. VM/허브처럼 여러 엣지가 같은 타겟으로 모이는 구조에서는 모든 라벨이 타겟 중심 한 점에 겹쳐 보인다. 소스·타겟의 절대 좌표로 `((sx+tx)/2, (sy+ty)/2)`를 직접 계산해 `points=[(mx, my)]`로 넘기면, 엣지마다 다른 위치에 라벨이 표시되어 겹침이 사라진다. 실제 drawio가 기본적으로 경로 중점에 라벨을 놓는지는 별개 문제이므로, 이 waypoint 지정은 미리보기 정확성과 실제 파일의 견고함을 동시에 확보하는 차원에서 항상 적용하라.
- **[MUST] 폭이 넓은 타겟에는 `entryX`/`entryY`를 반드시 명시하고, 접점 좌표로 검산**: 버스 바나 대형 컨테이너처럼 폭이 큰 도형을 타겟으로 삼으면 접점을 지정하지 않은 엣지가 전부 그 도형의 중앙 한 점으로 모여 부챗살이 됩니다. 소스의 `exitX`와 타겟의 `entryX`를 **같은 절대 x가 되도록** 계산해 넣으면 수직 스텁이 보장됨. 그리고 `render_preview()`는 exit/entry 스타일을 무시하고 항상 타겟 박스의 중심으로 선을 그리므로 **미리보기로는 이 문제를 검증할 수 없습니다** — `exitX*소스폭+소스x` 와 `entryX*타겟폭+타겟x` 를 직접 계산해 일치하는지 스크립트로 확인할 것.
- **[MUST] 버스 바(가로 막대) 표기는 소비자가 한 줄로 늘어설 수 있을 때만**: 공유 인프라를 가로 막대로 그리고 소비자들이 수직 스텁으로 붙는 표기는 깔끔해 보이지만, **소비자 그룹이 세로로 쌓인 레이아웃에서는 성립하지 않습니다.** 바 2개(예: DB·MQ)를 쓰면 아래쪽 소비자가 위쪽 바에 닿기 위해 다른 바를 가로질러야 하고, 이를 피하려 그룹을 재배치하면 **배치 순서가 도메인 의미가 아니라 배선 편의로 정해지는 주객전도**가 발생함. 실사례: 버스 표기로 전환했다가 Placement가 맨 왼쪽, Glance가 Nova와 Neutron 사이에 끼는 무의미한 순서가 나와 전량 폐기했다. 세로 스택 레이아웃에서는 "대표 엣지 1개 + 공통 라벨"(010 §7)을 쓰십시오.

## 5. 생성 직후 검증

- **[MUST] 생성 직후 렌더링 검증**: 090 문서의 ID/참조 무결성 검증만으로는 겹침·정렬·엣지 라우팅 문제를 못 잡습니다. XML 저장 직후 `layout_toolkit.py`의 `validate(path)`를 실행해 형제 겹침, **행 높이 불일치([WARN] 행 높이 불일치)**, **라벨 폭 초과([WARN] 라벨 폭 초과 의심)** 까지 확인할 것. 그다음 임시 렌더러를 매번 새로 짜는 대신 `layout_toolkit.py`의 `render_preview(path, out_png)`를 호출해 **엣지(연결선)까지 포함된** PNG를 실제로 열어 박스 정렬뿐 아니라 연결선이 다른 서브넷 내부를 뚫고 지나가지는 않는지 육안으로 확인한 뒤에만 완료를 선언할 것. 서드파티 아이콘을 썼다면 네트워크가 가능한 경우 `check_icon_urls(path)`로 이미지 URL 생존 여부도 확인할 것(죽은 링크는 [WARN], 네트워크 불가는 [INFO]로만 표시되며 완료 조건을 막지 않음). 말로 "정렬했습니다"라고 보고하는 대신, 반드시 눈으로 확인할 것. `validate()`가 행 높이 불일치를 경고하면 완료 선언 전에 반드시 `uniform_row()`를 적용해 재생성하고, 라벨 폭 초과를 경고하면 서브라벨 문장을 줄이거나 `<br>`로 나누십시오.
