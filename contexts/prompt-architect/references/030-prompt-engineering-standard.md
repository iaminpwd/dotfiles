# 프롬프트 구성과 유지보수

## 1. 필요한 지침 선별
- **[PREFER] 고유 정보:** 저장소 고유 경로, 검증 명령, 출력 계약, 반복 실패 방지책을 중심으로 작성할 것. 일반적인 역할 선언과 코딩 상식은 생략할 것.
- **[PREFER] 선택적 참조:** `SKILL.md`에는 사용 조건과 필요한 문서의 위치를 두고, 상세 문서는 해당 작업에서만 읽도록 안내할 것.

### 1.1 조항 등급 기준
- **[MUST]:** 안전·데이터 무결성·필수 검증·출력 계약처럼 위반 시 구체적인 실패가 발생하는 조건에 사용할 것.
- **[PREFER]:** 상황에 따라 다른 선택이 가능한 기본 권고에 사용할 것.
- **[NEVER]:** 예외 없는 금지 조건에 사용하고, 가능한 경우 안전한 대체 행동을 설명할 것.

## 2. 구조와 표현
- **[PREFER] 기존 구조 유지:** 기존 파일명과 문서 구성을 따르되, 새 문서는 역할에 맞게 구성할 것. 번호 접두사나 고정 템플릿은 필수가 아님.
- **[PREFER] 명확한 표현:** 짧고 이해하기 쉬운 문장으로 작성할 것. 전보체, 설명 비율, 특정 태그를 강제하지 않을 것.
- **[PREFER] 예시:** 출력 형식이나 자주 틀리는 조건을 설명할 때만 대표 예시를 추가할 것. 코드와 로그는 코드 블록 등으로 구분할 것.
- **[PREFER] 문서 크기:** 반복 내용을 먼저 줄이고, 독립적으로 읽을 필요가 있는 주제만 분리할 것. 기존 `prompt-lint.sh`의 크기 경고(일반 150줄, `-library.md` 250줄)는 검토 신호이며 분할 의무가 아님.

## 3. 저장소 호환성
- **[MUST] 스킬 진입점:** `SKILL.md`의 `name`과 `description` 프런트매터를 유지할 것.
- **[MUST] 참조 정합성:** 파일·조항을 삭제하거나 이름을 바꾸면 호출부, 라우팅 표, 문서 인용을 함께 확인할 것. 라우팅 표 변경 시 `bash bin/utils/generate-context-index.sh > contexts/INDEX.md`로 색인을 갱신할 것.
- **[PREFER] 중복 관리:** 같은 지침의 복사본 대신 필요한 참조를 연결하되, 참조를 따라 모든 문서를 읽는 절차는 만들지 않을 것.

## 4. 검증
- **[MUST] 프롬프트 린트:** 수정 후 `bash bin/linters/prompt-lint.sh`를 실행하고 오류를 해결할 것. 경고는 실제 영향이 있는지 검토할 것.
- **[PREFER] 효과 확인:** 길이나 형식만으로 성능 개선을 주장하지 말고, 대표 작업에서 성공 여부·불필요한 질문·도구 호출·비용을 비교할 것. 유료 평가는 `SKILL.md`의 승인 조건을 따를 것.
