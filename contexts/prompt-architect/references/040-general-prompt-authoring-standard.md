# 작업용 프롬프트 작성

## 1. 목적과 범위
- **[PREFER] 필요한 정보 확인:** 요청과 대화에서 목표, 입력, 대상 도구, 결과물 형태를 파악할 것. 결과에 중요한 정보가 없고 추론할 수도 없을 때만 질문할 것.
- **[MUST] 요청 범위 보존:** 사용자가 선택한 목표와 승인 범위를 유지할 것. 아키텍처 선호를 이유로 별도 작업을 추가하지 않을 것.
- **[PREFER] 출력 계약:** 파서·사용처·사용자 요구에 필요한 형식과 완료 조건을 명시할 것. 정해진 영문 문구나 공통 템플릿은 필수가 아님.

## 2. 정보와 표현
- **[PREFER] 맥락 선택:** 판단에 필요한 정보만 제공하고, 긴 자료는 위치와 사용 조건을 안내해 필요한 부분을 조회하도록 할 것.
- **[PREFER] 예시와 구조:** 출력 형식을 이해하는 데 도움이 될 때 예시나 구획을 추가할 것. 문장 종결 방식, 태그, 정보 배치 비율은 고정하지 않을 것.
- **[PREFER] 저장소 룰북:** 이 저장소에 배포하는 지침의 호환성·린트 기준은 `030-prompt-engineering-standard.md`를 참조할 것.

## 3. 실행 경계
- **[MUST] 승인 범위:** 읽기 전용 조사와 이미 승인된 작업은 진행할 수 있도록 할 것. 기존 승인을 반복해서 묻는 게이트를 추가하지 않을 것.
- **[MUST] 위험한 실행:** 인프라 삭제·마이그레이션·배포 등은 영향 범위와 실행 계획을 확인하고 해당 실행의 승인 여부를 확인하도록 할 것.
- **[PREFER] 실패 처리:** 실패 원인에 따라 대체 도구나 안전한 재시도를 선택하고, 진행에 필수인 권한·정보가 없거나 같은 실패가 반복되면 보고하도록 할 것.
- **[PREFER] 장기 작업 기록:** 재개에 필요한 결정과 진행 상태가 있을 때만 기록하도록 할 것. 매 턴 상태 파일 갱신을 강제하지 않을 것.

## 4. 완료 검토
- **[PREFER] 점검 기준:** 요청 범위가 유지되는지, 지침끼리 충돌하지 않는지, 불필요한 질문·문서 조회·산출물을 강제하지 않는지 확인할 것.
